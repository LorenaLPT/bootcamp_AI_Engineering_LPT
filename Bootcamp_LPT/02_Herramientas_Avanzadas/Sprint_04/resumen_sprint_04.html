HTTP y APIs REST con requests

Una API REST expone recursos (usuarios, productos...) a través de URLs y métodos HTTP estándar. Tu código actúa como cliente: construye un request, el servidor responde con JSON (habitualmente) y tú lo parseas.

Los métodos HTTP

MétodoPara quéIdempotente
GETLeer un recursoSí
POSTCrear un recurso nuevoNo
PUTReemplazar un recursoSí
PATCHModificar parcialmenteDepende
DELETEBorrar un recursoSí

Códigos de estado habituales

RangoSignificadoEjemplos
2xxÉxito200 OK, 201 Created, 204 No Content
4xxError del cliente400 Bad Request, 401 Unauthorized, 404 Not Found, 429 Too Many Requests
5xxError del servidor500 Internal, 503 Service Unavailable

GET con requests

import requests

r = requests.get("https://fakestoreapi.com/products/1", timeout=5)
r.status_code     # 200
r.json()          # dict parseado
r.headers         # dict de headers

# Con query params y auth
r = requests.get(url,
                 params={"limit": 5},
                 headers={"Authorization": f"Bearer {token}"},
                 timeout=5)

POST, PUT, DELETE

# Crear
r = requests.post(url, json={"title": "Nuevo", "price": 9.99})

# Reemplazar
r = requests.put(f"{url}/5", json={"title": "Actualizado"})

# Borrar
r = requests.delete(f"{url}/5")

Usa json=... (en lugar de data=...) para que requests serialice a JSON y añada el header Content-Type: application/json.

Función reusable get_json

def get_json(url: str, params=None, timeout: int = 5) -> dict:
    r = requests.get(url, params=params, timeout=timeout)
    r.raise_for_status()        # 4xx/5xx → HTTPError
    return r.json()

Manejo de errores y timeouts

from requests.exceptions import Timeout, HTTPError, RequestException

try:
    r = requests.get(url, timeout=2)
    r.raise_for_status()
    datos = r.json()
except Timeout:
    print("El servidor tardó demasiado")
except HTTPError as e:
    print(f"Error HTTP {e.response.status_code}")
except RequestException as e:
    print(f"Error de red: {e}")
✅ Siempre timeout: sin él, un servidor caído deja tu programa colgado para siempre. 5 segundos es un buen valor por defecto.

Errores típicos

  • Olvidar timeout: tu script se cuelga esperando una respuesta que nunca llega.
  • Asumir status_code == 200 sin comprobar: una API puede devolver 201, 204 o un 4xx.
  • Usar r.text en vez de r.json(): te quedas con un string sin parsear.
  • Hardcodear la URL o la API key en el código: usa variables y .env.
  • Enviar data=dict cuando la API espera JSON: usa json=dict.

IA Generativa con Gemini en Python ★

Primera integración con un Large Language Model. Pasas de "jugar en el chat" a invocar el modelo desde código: con una clave API, un entorno virtual aislado y una llamada que recibe texto (y a veces imágenes) y devuelve texto.

Setup profesional del proyecto

1
Entorno virtual por proyecto: python -m venv .venv → activarlo (.venv\Scripts\activate o source .venv/bin/activate). Aísla las dependencias de este proyecto de las de otros.
2
requirements.txt: lista de paquetes del proyecto. Se instala con pip install -r requirements.txt.
3
Fichero .env con secretos (GEMINI_API_KEY=...). NUNCA se sube a Git: añádelo al .gitignore.
4
Cargar .env en el código con python-dotenv o con os.environ.

Primera llamada a Gemini

import os
from dotenv import load_dotenv
from google import genai

load_dotenv()
cliente = genai.Client(api_key=os.getenv("GEMINI_API_KEY"))

respuesta = cliente.models.generate_content(
    model="gemini-3.6-flash",
    contents="Resume el libro '1984' en 2 líneas",
)
print(respuesta.text)

Partes de un prompt

🎭 System / Rol

Quién es el modelo y cómo debe comportarse. "Eres un revisor técnico que..."

📝 Tarea

Qué tiene que hacer. "Revisa este texto y devuelve 3 mejoras."

📎 Contexto

Los datos sobre los que opera: el texto a revisar, un snippet, una tabla.

Pedir salida JSON

respuesta = cliente.models.generate_content(
    model="gemini-3.6-flash",
    contents="""
        Devuelve un JSON con la forma:
        {"titulo": str, "autor": str, "anio": int}
        para el libro '1984'.
    """,
    config={"response_mime_type": "application/json"},
)
import json
datos = json.loads(respuesta.text)
✅ Parseo defensivo: aunque pidas JSON, siempre envuelve el json.loads en try/except. El modelo a veces mete texto extra o falla el formato.

Mensajes y conversación

mensajes = [
    {"role": "system", "content": "Eres un asistente breve."},
    {"role": "user",   "content": "¿Capital de Francia?"},
    {"role": "assistant", "content": "París."},
    {"role": "user",   "content": "¿Y de Alemania?"},
]

Cada mensaje tiene un rol (system, user, assistant) y un contenido. En el Sprint 05 verás cómo gestionar el historial.

Idea clave El LLM es un servicio HTTP más. Debajo del SDK hay un POST a una URL de Google con tu API key. Entenderlo así te ahorra misterios: timeouts, errores 4xx/5xx y parseo defensivo aplican igual.

Errores típicos

  • Subir el .env a Git: tu API key queda pública. Añádelo al .gitignore antes del primer commit.
  • Hardcodear la clave en el código "solo mientras pruebo": siempre se cuela a Git.
  • No activar el venv y acabar instalando todo en el Python global.
  • Asumir que la respuesta siempre vendrá en el formato pedido: parsea con try/except.
  • Olvidar comprobar el uso de tokens: una llamada mal construida puede costar más de lo esperado.

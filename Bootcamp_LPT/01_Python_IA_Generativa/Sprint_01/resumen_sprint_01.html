Markdown: documentar lo que haces

Markdown es un lenguaje de marcado ligero: con pocos símbolos (#, *, `) escribes texto plano que se renderiza como HTML. Lo vas a usar en celdas Markdown de Jupyter, en los README.md de tu repo y para dar instrucciones precisas a herramientas de IA, que entienden Markdown muy bien.

¿Por qué Markdown y no Word?

📄 Legible en crudo

El texto fuente ya se entiende sin renderizar.

🧬 Versionable con Git

Son archivos de texto: diffs limpios, histórico útil.

🤖 Lo entienden las IAs

Estándar de facto para instrucciones y respuestas de LLMs.

Bloque de código con resaltado

# Escribir así (fence con ```python)
```python
def saludar(nombre):
    return f"Hola, {nombre}"
```

Indicar el lenguaje activa el resaltado de sintaxis. Para variables o nombres de ficheros sueltos basta con código en línea entre acentos graves.

Cómo estructurar un buen documento

Patrón recomendado

  • Una o dos frases al principio con el propósito
  • Un solo # como título
  • Secciones con ## y ### en jerarquía
  • Listas para pasos; párrafos cortos
  • Código en bloques con el lenguaje correcto
  • Enlaces a documentación oficial al citar librerías

Esquema de informe o entrega

  • Introducción — qué y para qué
  • Datos / método — con qué y cómo
  • Resultados — qué sale
  • Conclusiones — qué significa
  • Referencias — enlaces
Idea clave Markdown no sustituye a Word: lo mejora para programadores. Es simple, legible, versionable y universal; lo verás en cada README, cada notebook y cada prompt de este bootcamp.

Errores típicos

  • Saltar niveles de encabezado (de # a ###) sin razón: rompe la jerarquía.
  • Olvidar líneas en blanco alrededor de listas o encabezados: algunos renderizadores no las separan.
  • Confundir Jupyter con GitHub: algunas extensiones GFM (notas al pie, <details>) no se renderizan igual.
  • Rutas de imágenes relativas al notebook: si lo mueves, se rompen.
  • Mezclar demasiado HTML dentro de la celda Markdown en Colab: a veces falla; mejor sintaxis Markdown pura.

Python I — variables, tipos y primeras operaciones ★

Primer contacto con el lenguaje. Toda la programación arranca aquí: guardar datos en variables, saber de qué tipo son, operar con ellos, mostrarlos por pantalla y pedirle datos al usuario. Es el bloque central del sprint: lo usarás a diario durante todo el bootcamp.

Variables: etiquetas con un valor

ingresos = 1000
gastos = 400
margen = ingresos - gastos
print(margen)   # 600

El = asigna el valor de la derecha a la etiqueta de la izquierda. No es "igual" matemático: x = x + 1 es válido y significa "nuevo x = viejo x más uno".

Buen nombre: ingresos_2009, precio_total, nombre_cliente. Minúsculas, descriptivo, con guiones bajos.
Mal nombre: x1, new var (con espacio), 2009_ingresos (empieza por número), def (palabra reservada).

Los cuatro tipos primitivos

TipoEjemploPara qué
int22, -7, 0Números enteros
float22.45, 3.0Números con decimales
str"hola", 'Bon Scott'Cadenas de texto
boolTrue, FalseVerdadero / falso
NoneTypeNoneAusencia de valor

Para preguntar el tipo: type(variable). Un string vacío "" sigue siendo str; distinto de None.

Conversión de tipos (casting)

int("98")              # 98
float("98.56")         # 98.56
str(42)                # "42"
int(24.69)             # 24  (trunca, no redondea)
round(24.69)           # 25  (redondea)
bool(0)                # False
bool("")               # False  (string vacío)
bool("hola")           # True
Lo que no se puede: int("98.56") falla (hay que pasar por float). float("98,56") también falla: Python usa punto decimal, no coma.

print: cuatro formas de mostrar

mes, beneficio = "septiembre", 800

# 1. Concatenación con +   (requiere str en todo)
print("Beneficios de " + mes + ": " + str(beneficio))

# 2. Comas: separa con espacios y no exige str()
print("Beneficios de", mes, "son", beneficio)

# 3. f-string (recomendado)
print(f"Beneficios de {mes}: {beneficio}")

# 4. Operador % (estilo antiguo, aún se ve)
print("Beneficios de %s: %s" % (mes, beneficio))
Por defecto, usa f-strings. Son legibles, permiten expresiones (f"{a+b}") y formato (f"{x:.2f}").

Operaciones aritméticas

OperadorQué haceEjemplo
+ - * /Suma, resta, mult., división10 / 4 == 2.5
**Potencia2 ** 10 == 1024
//División entera (trunca)11 // 3 == 3
%Resto (módulo)11 % 3 == 2

El módulo math trae lo complejo: math.sqrt(25), math.fabs(-4), math.acos(0). 4/0 lanza ZeroDivisionError; math.sqrt(-10) lanza ValueError.

Comparación y booleanos

x = 1
x == 1       # True   (igualdad: dos iguales)
x != 0       # True   (distinto)
x < 2        # True
1 == 1.0     # True   (int y float con mismo valor)
"AAA" == "BBB"  # False

# and / or / not combinan booleanos
(ram == 16 or ram == 32) and precio <= 800
Trampa clásica = asigna; == compara. if x = 5 es error de sintaxis, se escribe if x == 5.

Input: pedir datos al usuario

nombre = input("¿Cómo te llamas? ")
print(f"Encantado, {nombre}")

# input() SIEMPRE devuelve str, aunque teclees un número
edad = int(input("Edad: "))   # conversión explícita

Para números hay que convertir con int(...) o float(...). Si el texto no es convertible (p. ej. "hola"), lanza ValueError.

Métodos de str y primeras listas

Métodos de cadenas

s = "String de ejemplo"
s.upper()        # "STRING DE EJEMPLO"
s.lower()
s.replace("String", "Cadena")
len(s)           # 17
s[0]             # "S"  (indexado)

Listas

notas = [3, 6, 9, 10]
mezcla = ["texto", 1, 55.78, True]

notas[0]           # 3  (indexado desde 0)
notas[0] = 12      # se puede modificar
len(notas)         # 4
notas.append(7)     # añadir al final
notas.index(6)      # posición de un valor
notas.count(3)      # cuántas veces aparece
Idea clave Cada valor tiene un tipo, y el tipo decide qué puedes hacer con él. "4" + 6 es un error; int("4") + 6 funciona. Pensar en tipos te ahorra el 80% de los TypeError.

Errores típicos

  • NameError por teclear mal el nombre de la variable (gstos en vez de gastos) o usarla antes de asignarla.
  • SyntaxError por no cerrar comillas: "texto sin comilla final.
  • Mezclar str con número en +: "edad: " + 30 → TypeError. Usa str(30) o f-string.
  • Python es sensible a mayúsculas: Ingresos y ingresos son dos variables distintas.
  • Olvidar que input() devuelve str: operar directamente con el resultado da errores raros.
  • int("98.56") falla: hay que pasar por float primero (int(float("98.56"))).

Flujos de control: decidir y repetir

Hasta aquí el programa iba línea a línea de arriba abajo. Con los flujos de control el programa elige qué línea ejecutar (if) y repite bloques (for, while), y aprende a no romperse cuando algo falla (try/except).

Indentación: la sintaxis de Python

for num in numeros:
    if type(num) == int:
        print("es entero")   # 2 niveles dentro
    print("fin iteración")   # 1 nivel: sigue dentro del for
print("fuera del bucle")      # 0 niveles: fuera
Regla de oro: 4 espacios por nivel, siempre lo mismo en todo el archivo. No mezcles tabulador y espacios: Python lanza IndentationError.

Condicionales if / elif / else

mi_nota = 7

if mi_nota < 5:
    print("Suspenso")
elif mi_nota < 7:
    print("Bien")
elif mi_nota < 9:
    print("Notable")
else:
    print("Sobresaliente")

Se evalúa en orden: entra en la primera rama que sea verdadera y sale. elif y else son opcionales. Se pueden anidar (un if dentro de otro) pero demasiado anidamiento es señal de que falta refactorizar.

match / case — alternativa a cadenas de if

match dia.lower():
    case "lunes":    tarea = "Hacer la compra"
    case "martes":   tarea = "Ir al gimnasio"
    case _:          tarea = "Día libre"   # _ = por defecto

Útil cuando comparas una variable contra valores concretos. Para rangos o condiciones compuestas sigue siendo más claro un if/elif.

Bucle for — iterar sobre una secuencia

notas = [4, 5, 7, 3, 6]

for nota in notas:
    if nota >= 5:
        print(f"Aprobado con {nota}")
    else:
        print(f"Suspenso con {nota}")

Se itera sobre cualquier iterable: listas, strings, rangos, etc. En cada vuelta, la variable (nota) toma el siguiente valor.

range — generar enteros

list(range(5))         # [0,1,2,3,4]
list(range(2, 6))      # [2,3,4,5]
list(range(0, 10, 2))  # [0,2,4,6,8]
list(range(10, 0, -1)) # cuenta atrás

enumerate — índice + valor

names = ["Pedro", "Mariano", "Jose"]
for i, name in enumerate(names):
    print(i, name)
# 0 Pedro
# 1 Mariano
# 2 Jose

Bucle while — repetir mientras se cumple una condición

i = 0
while i < 5:
    print(i)
    i += 1          # ← sin esto, bucle infinito
print("Fin")
Bucle infinito: si olvidas modificar la variable de la condición, el while no sale nunca. Para pararlo en Jupyter / terminal: Ctrl + C.

break y continue

break — salir del bucle

for val in "string":
    if val == "i":
        break      # corta aquí
    print(val)
# s t r

continue — saltar a la siguiente

for val in "string":
    if val == "i":
        continue   # salta esta vuelta
    print(val)
# s t r n g

Manejo de errores con try / except

lista = [1, 2, 3]

try:
    print(lista[5])          # IndexError
except IndexError:
    print("Índice fuera de rango")
except Exception as e:
    print(f"Otro error: {e}")
finally:
    print("Se ejecuta pase lo que pase")
BloqueCuándo se ejecuta
trySiempre. Intenta correr el código "arriesgado".
except TipoErrorSi salta ese error concreto.
except (sin tipo)Captura cualquier error. Útil pero enmascara: usar con cabeza.
finallySiempre, haya fallado o no. Para cerrar ficheros, conexiones, etc.
Idea clave Decidir, repetir y recuperarse. Con if eliges rama, con for/while repites, con try/except evitas que un error puntual tumbe todo el programa.

Errores típicos

  • IndentationError: mezclar tabulaciones y espacios, o faltar sangría tras los dos puntos.
  • Olvidar los : al final de if, for, while, try.
  • Usar = en vez de == dentro de un if.
  • while infinito por no modificar la variable de la condición.
  • Intentar hacer "texto" + numero dentro del for: hay que convertir con str() o usar f-string.
  • except: genérico que oculta el bug real: mejor capturar el tipo concreto que esperas.
